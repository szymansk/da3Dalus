# Dependencies — da3Dalus / cad-modelling-service

> Generated by **Reversa Scout**. Two independent dependency trees live in
> this repository: a **Python backend** managed by Poetry 2.x, and a
> **JavaScript frontend** managed by npm. They share no package manager and
> no lock file.

| | Backend | Frontend |
|---|---|---|
| Manifest | `pyproject.toml` | `frontend/package.json` |
| Lock file | `poetry.lock` (**201** packages) | `frontend/package-lock.json` (**1 170** packages) |
| Package manager | Poetry 2.x (`package-mode = false`) | npm (`npm ci` in CI) |
| Runtime | Python **≥ 3.11, < 3.14** (Poetry group narrows to `< 3.13` because VTK 9.3.1 has no 3.13 wheel) | Node **22** (Node ≥ 24 breaks jsdom `localStorage`) |

A vestigial root `package.json` also exists, declaring only
`react-resizable-panels ^4.10.0`. It is not the frontend manifest and appears
to be an accident.

### 1.5 Backend dependency anomalies

1. **`openai` is declared but never locked.** `pyproject.toml` puts it in
   `[tool.poetry.dependencies]`, but the project uses PEP 621 `[project]`
   metadata; under Poetry 2.x `[tool.poetry.dependencies]` only *enriches*
   packages already listed in `[project].dependencies`. `openai` is absent
   from `[project].dependencies` and absent from `poetry.lock`. The AI
   copilot imports it lazily inside `_make_openai_client()`
   (`app/services/copilot_service.py:373`), so the app still starts — but on
   a clean `poetry install` (CI, Docker) the copilot will fail at first use
   with `ModuleNotFoundError`.
2. **Docker overrides the lock file.** The lock resolves CadQuery **2.7.0**,
   cadquery-ocp **7.8.1.1.post1**, VTK **9.3.1**. The Dockerfile force-installs
   CadQuery **2.6.1**, cadquery-ocp **7.9.3.0**, VTK **9.5.2** via
   `pip --no-deps`, and additionally runs `poetry lock --regenerate` at build
   time. The container therefore does **not** run the geometry kernel that
   local development and CI run.
3. **Most core dependencies are unpinned.** `fastapi`, `pydantic`,
   `sqlalchemy`, `alembic`, `uvicorn`, `shapely`, `casadi`, `jsonpickle` and
   `kaleido` carry no version constraint at all. Reproducibility rests
   entirely on `poetry.lock`.
4. **A git-fork dependency.** `ocp-vscode` points at
   `github.com/szymansk/vscode-ocp-cad-viewer.git` with no commit pin — the
   resolved code can change without a lock-file diff.
5. **Platform-gated core libraries.** `cadquery` and `aerosandbox` are excluded
   on `linux/aarch64` via environment markers. `app/main.py` probes
   `cad_available()` / `aerosandbox_available()` and skips registering the
   `cad`, `aeroanalysis`, `operating_points`, `airfoils` and `section_aoa`
   routers when they are missing — the API surface changes shape by platform.
6. **`ocp-vscode` drags a whole second web + notebook stack** (Flask,
   Werkzeug, IPython, Jupyter client/core, pyzmq, tornado) into the
   production dependency set for what is a development-only viewer.
7. **`pyproject.toml` changes require a committed `poetry.lock`** or CI
   install fails — the two must always move together.

### 2.3 Frontend dependency anomalies

1. **Next.js is pinned to a canary build** (`16.2.1-canary.33`), and
   `eslint-config-next` is pinned to the same canary. This is a pre-release
   framework carrying breaking changes relative to any stable 16.x — the
   repo's own `frontend/AGENTS.md` warns that the local
   `node_modules/next/dist/docs/` is the only reliable reference.
2. **`@types/three` sits in `dependencies`, not `devDependencies`** — it ships
   type declarations into the production dependency graph.
3. **Node-version coupling is not enforced.** Node 22 is mandatory
   (Node ≥ 24 breaks jsdom `localStorage`), CI hard-codes `node-version: "22"`,
   but there is no `engines` field and no `.nvmrc` to enforce it locally.
4. **A stray root `package.json`** declares `react-resizable-panels` outside
   the frontend workspace, with its own `package-lock.json` and a root
   `node_modules/`. It is unused by the build.
