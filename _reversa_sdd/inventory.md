## 1. What this project is

**da3Dalus** is an end-to-end **aircraft design toolchain** for RC / UAV
model aircraft, split into three cooperating code bases inside one
repository:

| Part | Path | Role |
|------|------|------|
| Backend service | `app/` | FastAPI REST API (v2) + FastMCP tool server. Business logic, persistence, CAD orchestration, aerodynamic analysis. |
| CAD/topology library | `cad_designer/` | Standalone CadQuery-based geometry and topology library (wings, fuselages, spars, printer settings, shape creators). Treated as read-only legacy by project convention. |
| Frontend workbench | `frontend/` | Next.js 16 App Router + React 19 design workbench: component tree, wing editor, 3D CAD viewer, analysis dashboards. |

The service generates parametric aircraft CAD via **CadQuery/OCCT**, runs
vortex-lattice / buildup aerodynamics via **AeroSandbox** (with a vendored
**AVL** Fortran binary as a secondary solver), persists everything through
**SQLAlchemy + Alembic**, and exposes the whole surface both as REST and as
**MCP tools** for AI-agent integration.

Authoritative in-repo architecture notes: `README.md`, `CLAUDE.md`,
`AGENTS.md`, `app/CLAUDE.md`, `.claude/rules/python-conventions.md`.

## 7. CI/CD

### GitHub Actions — `.github/workflows/test.yml` (the live pipeline)

Tiered strategy (gh-504), path-filtered by `dorny/paths-filter`:

| Job | Trigger | What it runs |
|-----|---------|--------------|
| `changes` | always | Detects `backend` (`app/**`, `cad_designer/**`, `pyproject.toml`, `poetry.lock`, `alembic/**`) vs `frontend` (`frontend/**`) changes |
| `fast` | PR + push to `main` | Python 3.12, `ruff check .`, then pytest excluding `slow`, `e2e`, `requires_cadquery`, `requires_aerosandbox`, `requires_avl`; `pytest-xdist -n auto`; coverage `--cov=app --cov=cad_designer --cov-fail-under=70` → `coverage.xml` artefact. Target ≤ 12 min |
| `full` | `ci-full` PR label or manual dispatch | Adds back CAD/ASB/AVL-dependent tests (`-m "not slow and not e2e"`). No coverage upload |
| `nightly` | cron `0 3 * * *` + dispatch | Full suite, **all markers**, Python matrix 3.11 + 3.12, sequential (memory-heavy), 3000 s timeout |
| `frontend` | frontend changes | Node 22, `npm ci`, `npm run lint`, **`npx tsc --noEmit`**, `npm run test:unit -- --coverage` → `lcov.info` artefact |
| `sonarcloud` | after `fast` + `frontend` | `SonarSource/sonarcloud-github-action@v5`, consumes both coverage artefacts |

Disabled workflows present: `claude-code-review.yml.disabled`,
`claude.yml.disabled`.

Issue templates: `.github/ISSUE_TEMPLATE/{bug,feature,task}.md`.
Prompt archive: `.github/prompts/` (6 design/plan prompts).

## 10. Database — DDL, migrations, ORM models (list only)

**Engine:** SQLite by default (`sqlite:///./db/test.db`), overridable via
`SQLALCHEMY_DATABASE_URL` (PostgreSQL example documented in `.env.example`).
SQLite connections get `journal_mode=WAL`, `synchronous=NORMAL`,
`busy_timeout=30000`, `check_same_thread=False`, 30 s timeout — required
because assumption recompute holds long write transactions.

**Session/transaction:** `app/db/session.py` — `get_db()` dependency commits
on success and rolls back on exception. Services must **not** call
`db.begin()`.

**Migrations:** `alembic/versions/` — **62 revision files**, single head
`d8015f98814c` (`gh1083_wood_stock_types_and_abachi`). No DDL `.sql` files;
schema is defined entirely by the ORM + migrations.

**ORM model modules (21)** — `app/models/`:
`aeroplanemodel.py`, `airfoil.py`, `airfoil_low_re.py`, `analysismodels.py`,
`avl_geometry_events.py`, `avl_geometry_file.py`, `component.py`,
`component_tree.py`, `component_type.py`, `computation_config.py`,
`construction_part.py`, `construction_plan.py`, `flight_envelope_model.py`,
`flightprofilemodel.py`, `mission_objective.py`, `mission_preset.py`,

## 12. Anomalies & gaps worth flagging

1. **`app/api/v1/` does not exist.** `CLAUDE.md` and `app/CLAUDE.md` both
   describe a "legacy v1" REST surface; the tree contains only
   `app/api/utils.py` and `app/api/v2/`. The v1 surface has been removed but
   the documentation still references it.
2. **`azure-pipelines.yml` is stale.** It points at
   `docker/Dockerfile.client.amd64.dockerfile`, which is absent, and triggers
   on a `master` branch while the repository's default branch is `main`.
   GitHub Actions (`test.yml`) is the live pipeline.
3. **`Dockerfile` base is ARM-only for the AVL stage** (`arm64v8/ubuntu:22.04`)
   while `azure-pipelines.yml` targets amd64 — the container story is
   inconsistent across the two pipelines.
4. **Version pinning drift between Poetry and Docker.** `poetry.lock` resolves
   CadQuery 2.7.0 / cadquery-ocp 7.8.1.1 / VTK 9.3.1, but the Dockerfile
   force-installs CadQuery 2.6.1 / cadquery-ocp 7.9.3.0 / VTK 9.5.2 via
   `pip --no-deps`. Container and local environments do not run the same
   geometry kernel.
5. **Two independent `Settings` classes** (`app/core/config.py` and
   `app/settings.py`), both reading `.env`, with overlapping concerns
   (`base_url` vs `UVICORN_HOST`). `app/db/session.py` additionally reads
   `SQLALCHEMY_DATABASE_URL` through raw `os.getenv`, bypassing both — which
   contradicts the project's own "all configuration goes through
   `core/config.py`" rule.
6. **`openvsp` is an out-of-tree optional dependency** (documented at length
   in `pyproject.toml`): it must be installed manually because no compatible
   wheel exists for the runtime Python. The application degrades gracefully
   via `app/converters/openvsp_adapter.py`. A `vendor/openvsp` tree exists.
7. **`cad_designer/` is deliberately excluded from SonarCloud analysis**
   (`sonar.exclusions`) and from ruff (`extend-exclude`), and is treated as
   read-only by project convention (new `AbstractShapeCreator` subclasses are
   the only permitted additions, plus one approved `Turbulator` exception).
   Its ~22 000 LOC are effectively unlinted and unanalysed.
8. **`ruff` also excludes `test/`, `alembic/`, `Avl/`, `exports/`** — a
   documented backlog of ~400 accumulated violations.
9. **Hard-coded German user-facing strings** in backend error handlers
   (`app/main.py`: `"name existiert bereits"`, `"Ungültige Eingabedaten"`)
   while the frontend is English-only by convention. A latent i18n
   inconsistency in the API contract.
10. **The repository root is heavily polluted with runtime and agent
    artefacts** — `tmp/`, `exports/`, `.playwright-report/`, `test-results/`,
    `claude-auto-resume.log`, `coverage.xml`, `db/*.bak-*`, `test.png`,
    `.worktrees/`, `.ralph/`, `.superpowers/`. Several are gitignored, but
    they make the surface noisier than the actual codebase.
11. **CORS is fully open** (`allow_origins=["*"]` with
    `allow_credentials=True`) — flagged in `app/main.py` with a comment
    admitting it was copied from another backend.
12. **A live SQLite database is committed** (`db/test.db`, plus two dated
    backups and WAL files) and is copied into the Docker image.
